=====================================================================
 WARDEN 깨끗 설치 시연 가이드 (헤드리스 데비안 minimal + setup.py 라이브)
 작성 2026-11-09
=====================================================================

[ 목적 ]
 OVA(이미 설치된 상태)를 불러오는 대신, 깨끗한 가벼운 리눅스에 setup.py 로
 "실제 설치되는 과정"을 라이브로 보여주기 위한 구성. 데스크톱(GUI) 없는
 헤드리스 데비안이라 지금 칼리 VM 보다 훨씬 가볍다. 대시보드는 노트북
 브라우저로 보므로 VM 안에 화면이 필요 없다.

[ 전체 그림 ]
   학교 노트북 (실물, VirtualBox)
    ├─ 보안 서버  (데비안 minimal)  eth0 192.168.56.10  <- WARDEN 라이브 설치
    │                               eth1 192.168.57.10  <- 노트북 브라우저로 대시보드(:8080)
    └─ 공격자     (데비안 minimal)        eth0 192.168.56.20
       * 공격자는 VirtualBox "내부 네트워크 lab" 으로 서버하고만 연결 (인터넷 없음)
         -> 격리의 핵심은 공격자가 인터넷과 끊겨 있다는 것. 공격 트래픽이 샐 길이 없음
       * 서버는 NAT(인터넷)를 그대로 둬도 된다 (떼지 않아도 됨). 서버가 인터넷에 붙어
         있어도, 공격자가 서버를 거쳐 인터넷으로 나가지는 못한다 (서버는 패킷을
         전달하지 않음: ip_forward 기본값 0)
       * 서버의 eth1 은 호스트 전용 어댑터(게이트웨이 192.168.57.1) = 노트북

[ 왜 배포판을 고르냐 ]
 - 추천: 데비안 12 minimal (또는 우분투 서버 minimal)
   -> apt 지원 + systemd 있음. setup.py 가 배포판 자동 감지하고
      "자동 시작 서비스 등록(warden.service)" 까지 보여줄 수 있음
 - 록키 minimal 도 되지만(dnf) 더 무겁고 EPEL 받느라 인터넷을 더 씀
 - Alpine 은 쓰지 말 것: apk + musl + systemd 없음 -> setup.py 미지원

[ 가장 중요한 주의 - 인터넷 타이밍 ]
 setup.py 는 apt 로 패키지(python3-scapy, iptables 등)를 "인터넷에서" 받는다.
 -> 서버에는 NAT 어댑터를 붙여 둔다 (설치 후에도 떼지 않아도 됨). 서버가
    인터넷에 붙어 있어도 공격자는 격리돼 있어 실습 안전에는 지장 없다.
 -> NAT 는 VirtualBox 호스트(노트북)의 인터넷을 빌려 쓰므로, setup.py 를
    돌리는 순간 노트북이 인터넷에 연결돼 있어야 한다.
 -> 발표장에 인터넷이 아예 없다면: 준비 때 미리 설치를 끝내 두고 스냅샷으로
    보여주거나(라이브 느낌은 줄어듦), 설치 순간만 테더링 등으로 인터넷을
    확보할 것. "라이브 설치"는 그 순간 인터넷이 필수.
 -> 반대로 공격자는 인터넷이 없어야 한다 (lab 망만). 공격 도구는 설치할 때만
    잠깐 NAT 로 받고, 끝나면 공격자의 NAT 를 떼서 서버하고만 남긴다.


=====================================================================
 PART A. 보안 서버 만들기 (깨끗 데비안 + setup.py 라이브 설치)
=====================================================================

A-0. VM 만들기 (VirtualBox)
 - 종류: Linux / Debian (64-bit)
 - 메모리: 2048 MB 면 충분 (헤드리스라 가벼움. 1024 로도 동작은 함)
 - CPU: 1~2개
 - 디스크: 12 GB 동적 할당

A-1. 데비안 minimal 설치
 - debian-12.x.x-amd64-netinst.iso 로 설치
 - 소프트웨어 선택 화면에서:
     [ ] Debian desktop environment   <- 끄기 (GUI 안 씀)
     [x] SSH server                    <- 켜기 (노트북에서 파일 넣고 접속용)
     [x] standard system utilities
 - 일반 사용자 하나 만들기 (예: user). root 비밀번호도 설정
 - 설치 끝나면 재부팅

 (선택) 인터페이스 이름을 eth0/eth1 로 맞추고 싶으면 - 안 해도 됨:
   setup.py 는 이름이 아니라 IP(192.168.56.x)로 감시 인터페이스를 찾으므로
   enp0s3 같은 이름이어도 상관없다. 그래도 통일하고 싶으면 설치 후
   /etc/default/grub 의 GRUB_CMDLINE_LINUX 에 net.ifnames=0 biosdevname=0 을
   넣고 sudo update-grub 후 재부팅.

A-2. 네트워크 어댑터 3개 (VM 설정 -> 네트워크)
 - 어댑터 1: 내부 네트워크, 이름 "lab"      (= eth0, 감시망 192.168.56.10)
 - 어댑터 2: 호스트 전용 어댑터            (= eth1, 관리망 192.168.57.10)
      * 호스트 전용 네트워크가 없으면 먼저 만들 것:
        VirtualBox -> 도구 -> 네트워크 -> 호스트 전용 -> 만들기
        -> IPv4 주소 192.168.57.1 / 마스크 255.255.255.0, DHCP 끄기
        (migration_guide.txt 4-1 과 같은 구성)
 - 어댑터 3: NAT                          (인터넷용. 그대로 둬도 됨 - 떼지 않아도 된다)

A-3. 고정 IP 설정 (데비안 minimal 은 /etc/network/interfaces 사용)
 먼저 인터페이스 이름 확인:  ip -o link show   (예: enp0s3 enp0s8 enp0s9)
 보통 어댑터 1=enp0s3, 2=enp0s8, 3=enp0s9 (NAT) 순서.
 sudo nano /etc/network/interfaces 에 아래를 맞게 적는다
 (이름은 위에서 확인한 것으로 바꿔 쓸 것):

   # 감시망 (lab 내부망) - 어댑터 1
   auto enp0s3
   iface enp0s3 inet static
       address 192.168.56.10
       netmask 255.255.255.0

   # 관리망 (호스트 전용, 노트북에서 대시보드 접속) - 어댑터 2
   auto enp0s8
   iface enp0s8 inet static
       address 192.168.57.10
       netmask 255.255.255.0

   # 인터넷 (NAT) - 어댑터 3. 그대로 둬도 된다. DHCP 로 자동
   allow-hotplug enp0s9
   iface enp0s9 inet dhcp

 적용:  sudo systemctl restart networking   (또는 재부팅)
 확인:  ip -4 addr  로 56.10 / 57.10 가 보이고,
        ping -c2 8.8.8.8 로 인터넷(NAT)이 되는지 확인

A-4. WARDEN 소스를 서버에 넣기
 소스(공유 폴더 또는 릴리스 zip)를 서버에 넣는다. 서버에 NAT 가 있으면
 공개 저장소/릴리스는 인터넷에서 바로 받을 수도 있지만, 저장소가 비공개라
 토큰이 필요하니 노트북에 받아 둔 파일을 scp 로 넣는 게 간단하다:

 [ 방법 1: 노트북에서 scp ] - 비공개 저장소여도 되고, 인터넷 없이도 됨
   노트북 PowerShell 에서 (서버에 SSH server 를 켰으므로):
     scp "C:\Share folder\release\WARDEN-v2.2.zip" user@192.168.57.10:~/

   서버에서:
     unzip ~/WARDEN-v2.2.zip -d ~/warden_src
     cd ~/warden_src/WARDEN*    (압축 안에 폴더가 하나 더 있으면 그 안으로)

 * unzip 이 없으면 설치 창(NAT 켜진 동안) 에  sudo apt install -y unzip
 * zip 대신 공유 폴더(Guest Additions)나 USB 로 넣어도 된다.

 [ 방법 2: GitHub 에서 바로 받기 ] - 서버에 NAT 인터넷이 있으므로 가능
  저장소: https://github.com/ADVI50R/WARDEN
  ※ 지금은 비공개(private)라 토큰이 필요하다. 공개(public)로 바꾼 뒤에는
    아래가 토큰 없이 그대로 된다.

  (가) git 으로 clone (git 은 데비안 minimal 에 없으면 먼저 설치):
     sudo apt install -y git
     git clone https://github.com/ADVI50R/WARDEN.git
     cd WARDEN

  (나) git 없이 tar 로 (curl, tar 는 기본으로 있음):
     curl -L -o warden.tar.gz https://github.com/ADVI50R/WARDEN/archive/refs/heads/main.tar.gz
     tar -xzf warden.tar.gz
     cd WARDEN-main

  (다) 정해진 버전(릴리스)을 받기 - 공개 전환 + 릴리스 등록 후:
     curl -L -o WARDEN-v2.2.zip https://github.com/ADVI50R/WARDEN/releases/download/v2.2/WARDEN-v2.2.zip
     unzip WARDEN-v2.2.zip && cd WARDEN-v2.2

  어느 방법이든 받은 폴더 안(README·setup.py 가 보이는 위치)에서 A-5 로 간다.
  ※ 실습 서버(격리된 칼리)는 인터넷이 없으니 GitHub 를 직접 못 받는다 ->
    인터넷 되는 PC 에서 받아 공유 폴더/scp 로 옮긴다. 이 가이드의 깨끗
    데비안 서버는 NAT 가 있어 직접 받을 수 있다.

A-5. setup.py 라이브 설치  ★ 시연의 핵심
 반드시 NAT(어댑터 3)가 켜져 인터넷이 되는 상태에서:

     sudo python3 setup.py

 - 화면이 순서대로 보여준다: 환경 확인(배포판=데비안 감지, 파이썬,
   가상화/WSL, 방화벽 경고) -> 외부 패키지 설치(apt) -> IP 구성 확인
   (감시 eth0=192.168.56.10, 대시보드 host=192.168.57.10, 화이트리스트
   192.168.57.1 자동) -> 설정 고르기 -> 단계별 설치 -> 완료 화면에
   대시보드 주소와 토큰
 - "자동 시작 서비스(systemd)" 를 켜면 warden.service / warden-dashboard.service
   가 등록된다 (데비안이라 systemd 있음 -> 이 대목이 보여짐). 시연이면 켜길 권장
 - dry-run(탐지만)으로 시작하도록 두기 (실제 차단은 나중에 슬라이드로)
 - 화면 없이 기본값으로 한 번에 가려면:  sudo python3 setup.py --yes

A-6. 설치 확인
 - 셸 설정 다시 읽기:  source ~/.bashrc    (setup.py 가 단축명령을 넣음)
 - 상태:  wstatus         (dry-run / eth0 / 서비스 관리 여부 표시)
 - 노트북 브라우저에서  http://192.168.57.10:8080  -> 완료 화면의 토큰으로 로그인
 - 안 열리면: 서버에서 wstatus 로 대시보드가 떴는지, eth1(57.10)이 올라왔는지,
   노트북의 호스트 전용 어댑터가 192.168.57.1 인지 확인

A-7. (서버 NAT 는 떼지 않아도 된다)
 설치가 끝나도 서버의 어댑터 3(NAT)은 그대로 둬도 된다. 서버가 인터넷에
 붙어 있어도 실습 안전에는 지장이 없다 - 격리는 "공격자가 인터넷과 끊겨
 서버하고만 연결"되는 것으로 확보되기 때문이다 (PART B 참고).
 (원하면 떼도 되지만, 둬도 패키지 추가 설치·업데이트가 편하다.
  단, 서버에서 ip_forward 를 켜지는 말 것 - 기본값 0 이면 공격자가
  서버를 거쳐 인터넷으로 나가지 못한다.)


=====================================================================
 PART B. 공격자 서버 구성
=====================================================================

공격자는 WARDEN 설치 대상이 아니라 "공격 도구만" 있으면 된다.
서버와 똑같이 가벼운 데비안 minimal 로 만든다.

B-0. VM 만들기: A-0 과 동일 (메모리 1024~2048 로 충분, 디스크 10 GB 면 됨)

B-1. 데비안 minimal 설치: A-1 과 동일
      - 소프트웨어 선택에서 Debian desktop environment 끄기
      - SSH server 켜기, standard system utilities 켜기

B-2. 네트워크 어댑터 (VM 설정 -> 네트워크)
      - 어댑터 1: 내부 네트워크, 이름 "lab"  (= eth0, 192.168.56.20)
            * 서버의 어댑터 1 과 "lab" 이름이 똑같아야 서로 연결된다
      - 어댑터 2: NAT                         (도구 설치 때만, 설치 후 끈다)

B-3. 고정 IP (/etc/network/interfaces, 이름은  ip -o link show  로 확인):
         # lab 내부망 - 어댑터 1
         auto enp0s3
         iface enp0s3 inet static
             address 192.168.56.20
             netmask 255.255.255.0

         # 인터넷(NAT) - 어댑터 2, 도구 설치용. 끝나면 끈다
         allow-hotplug enp0s8
         iface enp0s8 inet dhcp
      적용:  sudo systemctl restart networking
      확인:  ip -4 addr (56.20 보임),  ping -c2 8.8.8.8 (NAT 인터넷)

B-4. 공격 도구 설치 (NAT 켜진 동안):
         sudo apt update
         sudo apt install -y nmap hping3 netcat-traditional python3-scapy tcpdump
      * SSH 로그인 성공 테스트(8번)에 sshpass 도 쓰면:
         sudo apt install -y sshpass
      * netcat 은 데비안에서 netcat-traditional 을 쓰면 -p 옵션이 그대로 먹는다
        (nmap 패키지의 ncat 과 옵션이 다름)

B-5. 설치 끝나면 공격자의 NAT(어댑터 2)를 "케이블 연결 끊기" 하거나 제거 -> lab 망만 남김
      * 이게 실습 격리의 핵심이다: 공격자는 인터넷과 끊겨 서버하고만 연결된다.
        (서버는 NAT 를 둬도 되지만, 공격자는 반드시 뗀다)

B-6. 확인
      - 서버부터 켜서 다 올라온 뒤 공격자를 켠다
      - 공격자에서:  ping -c2 192.168.56.10   (서버로 통하는지)
      - 공격자 프롬프트에서만 공격 명령을 친다
        (서버 창에서 치면 자기 자신 공격이라 탐지 안 됨)

 ※ 빠르게 가야 하면 기존 공격자 OVA(도구 다 들어 있음)를 대신 불러와도 되지만,
   이번 구성은 데비안 minimal 로 통일한다. OVA 는 폴백용으로만 남겨 둔다.


=====================================================================
 PART C. 시연 흐름 (권장 순서)
=====================================================================
 1. (선택) 제거 먼저 보여주기: 이미 설치된 서버라면  uninstall.py 로 지우는 것부터
    보여주고 -> 깨끗해진 상태에서 setup.py 재설치. "설치/제거 자동화" 로 완결
 2. 보안 서버에서  sudo python3 setup.py  라이브 설치 (A-5)
 3. 노트북 브라우저로 대시보드 로그인, dry-run 확인
 4. 공격자에서 공격 -> 대시보드 탐지 로그 확인 (명령은 attack_test_memo.txt /
    attack_test_guide.md). 마지막에 슬라이드를 "실제 차단"으로 한 번
 5. 끝나면 슬라이드 dry-run 으로, 꺼둔 규칙 다시 켜기

 PART D. 꼬였을 때 폴백 (보험)
=====================================================================
 - 라이브 설치가 발표 중 꼬이면: 기존 서버 OVA(설치 완료본) 또는 스냅샷
   "시연준비완료3" 로 바로 갈아타서 공격 실습은 이어간다
 - 그러니 OVA 서버본을 지우지 말고 백업으로 둘 것
 - 흔한 문제:
   * apt 가 실패 -> 노트북(호스트)에 인터넷이 없거나 NAT 어댑터가 없음
     (setup.py 는 설치 순간 인터넷 필수. 서버 NAT 는 그대로 두면 됨)
   * 대시보드 안 열림 -> 노트북 호스트 전용 어댑터가 192.168.57.1 인지,
     서버 eth1 이 57.10 인지, wstatus 로 대시보드가 떴는지
   * 공격이 탐지 안 됨 -> 공격자 프롬프트에서 쳤는지(서버 아님), 규칙이 켜졌는지,
