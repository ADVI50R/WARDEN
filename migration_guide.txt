==================================================================
  Guardian 관제 실습 - 학교 서버 가상 컴퓨터로 옮기기 가이드
==================================================================

[ 목표 ]

  지금 구성 (실제 PC > Windows 10 VM > VirtualBox > 칼리 2대) 을
  학교 서버에서 받은 가상 컴퓨터로 옮긴다.

  옮기는 것은 "칼리 VM 2대" (보안 서버, 공격자) 뿐이다.
  Windows 10 VM 자체와 DWAgent 는 옮기지 않는다.
  (guardian.py, rules/, logs/, 대시보드 토큰은 모두 보안 서버 칼리
   안의 ~/guardian 에 있으므로 칼리 VM 을 옮기면 함께 따라간다)

[ 진행 순서 ]

  0. 먼저 확인할 것 (학교 가상 컴퓨터 조건)
  1. 옮기는 방법 고르기
  2. 방법 A: VM 통째로 옮기기 (내보내기 / 가져오기)
  3. 방법 B: 파일만 옮기고 새로 만들기 (가볍고 안전)
  4. 옮긴 뒤 설정 다시 맞추기
  5. 동작 확인
  6. 문제 해결 모음

각 단계가 끝날 때마다 [확인] 항목을 체크하고 다음으로 넘어가세요.


==================================================================
 0. 먼저 확인할 것 (학교 가상 컴퓨터 조건)
==================================================================

  학교에서 받은 가상 컴퓨터가 어떤 종류인지에 따라 방법이 달라진다.
  아래 항목을 확인해서 메모한다.

  [ ] 운영체제: Windows / Linux 중 무엇인가?
  [ ] 어떤 가상화 프로그램 위에서 도는가? (VMware, Proxmox, Hyper-V ...)
  [ ] 메모리 / CPU / 디스크 여유 (칼리 2대 기준 아래 표 참고)
  [ ] 중첩 가상화 (그 가상 컴퓨터 안에서 또 VM 을 돌리는 것) 가 허용되는가?
      - 관리자(교수님/조교)에게 문의: "VM 안에서 VirtualBox 를 쓸 수
        있게 중첩 가상화를 켜 주실 수 있나요?"
  [ ] 인터넷: 되는가? 학교 외부에서 접속하는 방법은? (VPN, 포트 등)
  [ ] 관리자 권한(root/Administrator) 이 있는가?
  [ ] 공유 폴더 / 파일 전송 방법 (USB, 네트워크 드라이브, scp ...)

  [ 필요 자원 (대략) ]
    메모리 ..... 최소 6GB (칼리 2GB x 2 + 운영체제 2GB 이상)
    CPU ........ 4개 권장
    디스크 ..... 40GB 이상 여유 (칼리 VM 1대당 20GB 안팎 + 내보내기 파일)

  [ 판단 ]
    중첩 가상화 가능 + VirtualBox 설치 가능  -> 방법 A (통째로 옮기기)
    중첩 가상화 불가                          -> 방법 B 로 "칼리 2대" 를
      만들 수 없으므로, 아래 [3-5] 대안(한 대에 합치기)을 보거나
      학교에 VM 을 2개 요청한다.
    학교 가상화가 VMware/Proxmox 이고 VM 을 직접 만들 수 있음
                                              -> 방법 A 의 [2-6] 참고

  ※ 이 부분이 정해지지 않았으면 먼저 사용자(팀)와 상의한 뒤 진행한다.

[확인] 위 항목을 메모했고, 어느 방법으로 갈지 정했다


==================================================================
 1. 옮기는 방법 고르기
==================================================================

  방법 A. VM 통째로 옮기기
    - 지금 환경 그대로 가져온다 (설정, 한글 글꼴, 규칙, 차단 기록 유지)
    - 파일이 크다 (칼리 1대당 수 GB ~ 10GB 이상)
    - 학교 쪽에서 VirtualBox 등이 돌아야 한다

  방법 B. 파일만 옮기고 새로 만들기
    - ~/guardian 폴더(약 0.3MB) 만 가져와서 새 칼리에 올린다
    - 칼리 설치와 패키지 설치를 다시 해야 하지만, 깨끗하게 시작된다
    - 인터넷이 필요하다 (패키지 설치)

  어느 쪽이든 먼저 [1-1] 백업은 반드시 한다.

[1-1] 백업 (공통, 꼭!)

  1) 칼리 두 VM 을 정상 종료한다 (sudo poweroff)
  2) VirtualBox > 보안 서버 선택 > 스냅샷 탭 > 찍기
     이름: 이전전백업   (공격자도 동일)
  3) 보안 서버 칼리에서 guardian 폴더 압축 (VM 켠 상태에서 먼저 해도 됨)
       cd ~
       tar czf /media/sf_share/guardian_backup.tgz guardian
     ※ rules/ 와 logs/ 와 dashboard_config.json 이 포함되는지 확인
       tar tzf /media/sf_share/guardian_backup.tgz | grep -E "rules|logs|dashboard_config"

[확인] guardian_backup.tgz 가 공유 폴더에 있고, 스냅샷이 찍혔다


==================================================================
 2. 방법 A: VM 통째로 옮기기 (내보내기 / 가져오기)
==================================================================

[2-1] 내보내기 전에 정리 (Windows 10 VM 의 VirtualBox 에서)

  - 두 VM 모두 "전원 꺼짐" 상태 (저장됨 이면 저장된 상태 삭제)
  - 공유 폴더 설정은 내보내기에 들어가지 않는다 (옮긴 뒤 다시 추가)
  - 스냅샷이 많으면 파일이 커진다. 필요 없는 스냅샷은 삭제한다
    (삭제는 "병합" 이라 시간이 걸릴 수 있음. 꼭 한 번에 하나씩)

[2-2] 내보내기 (Windows 10 VM 의 VirtualBox)

  파일 > 가상 시스템 내보내기 (Export Appliance)
   1) 보안 서버 선택 > 다음
   2) 형식: OVF 1.0 / 파일: E:\export\server.ova   (확장자 .ova)
   3) "MAC 주소 정책": 모든 네트워크 어댑터의 MAC 주소 포함하지 않음
      (옮긴 뒤 새 MAC 이 생성되어 학교 네트워크와 충돌 방지)
   4) 내보내기. 공격자도 똑같이 -> E:\export\attacker.ova

  명령줄로 하려면:
    cd "E:\VirtualBox"
    .\VBoxManage export "보안 서버" -o "E:\export\server.ova"
    .\VBoxManage export "공격자" -o "E:\export\attacker.ova"

  ※ 파일 크기를 확인한다 (보통 각각 3~8GB)
    (Get-Item E:\export\*.ova | Select Name,@{n='GB';e={[math]::Round($_.Length/1GB,2)}})

[확인] server.ova, attacker.ova 두 파일이 만들어졌다

[2-3] 파일 옮기기

  파일이 크므로 방법을 고른다.
   - 공유 폴더(Z:) 를 통해 실제 PC 로 복사 -> USB 로 학교 서버 쪽으로 이동
   - 학교 네트워크 드라이브 / scp / 클라우드 (용량 주의)
  전송 후 파일 크기가 같은지 확인한다 (크기가 다르면 다시 복사).
  체크섬을 보려면:
    Get-FileHash E:\export\server.ova -Algorithm SHA256
  양쪽 결과가 같아야 한다.

[2-4] 학교 가상 컴퓨터에 VirtualBox 설치

  - 설치 파일은 virtualbox.org 에서 받는다 (같은 7.x 대 버전 권장)
  - Windows 이면 설치 후 재부팅
  - Linux 이면 배포판 패키지 또는 공식 .deb/.rpm
  - 중첩 가상화가 켜져 있는지 확인:
      Windows: 작업 관리자 > 성능 > CPU > 가상화: 사용
      Linux:   egrep -c '(vmx|svm)' /proc/cpuinfo   (0 보다 커야 함)

[2-5] 가져오기 (학교 가상 컴퓨터의 VirtualBox)

  파일 > 가상 시스템 가져오기 (Import Appliance)
   1) server.ova 선택 > 다음
   2) 이름: 보안 서버 / CPU 2개 / 메모리 2048MB 확인
   3) "모든 네트워크 어댑터의 MAC 주소 다시 초기화" 체크 (필수)
   4) 가져오기. attacker.ova 도 똑같이

  [ 가져온 직후 설정 맞추기 (켜기 전에!) ]
   - 네트워크 어댑터 1: 내부 네트워크, 이름 lab (두 VM 모두 똑같이)
   - 보안 서버 어댑터 2: 호스트 전용 (아래 4단계에서 만든다)
   - 공유 폴더가 필요하면 다시 추가
   - 디스플레이: VMSVGA / 비디오 메모리 128MB

[확인] 목록에 보안 서버, 공격자가 보인다 (아직 켜지 않음)

[2-6] 학교 쪽이 VMware / Proxmox / Hyper-V 일 때

  VirtualBox 의 OVA 는 OVF 표준이라 대부분 가져올 수 있다.
   - VMware (ESXi / Workstation): 파일 > OVF/OVA 열기
   - Proxmox: 먼저 ova 를 풀고 (tar xf server.ova)
       qm importovf <VMID> server.ovf <저장소>
     또는 vmdk 를 qcow2 로 변환 (qemu-img convert -f vmdk -O qcow2)
   - Hyper-V: vmdk 를 vhdx 로 변환 후 새 VM 에 연결
  이 경우 "내부 네트워크 lab" 은 해당 프로그램의 "격리된 가상 스위치"
  (VLAN/호스트 없는 브리지) 로 바꿔서 만든다.
  어댑터 종류는 Intel e1000 이 가장 호환이 잘 된다.
  ※ 학교 환경마다 달라서, 이 부분은 해당 화면을 보고 같이 진행하는 게 좋다.


==================================================================
 3. 방법 B: 파일만 옮기고 새로 만들기 (가볍고 안전)
==================================================================

  [3-1] 가져갈 파일 (공유 폴더 등 어느 방법이든)
    - guardian_backup.tgz  (1-1 에서 만든 것, 약 0.3MB)
    - 또는 guardian_dashboard.zip

  [3-2] 학교 가상 컴퓨터에서 칼리 2대 새로 만들기
    -> lab_setup_guide.txt 의 2~6 단계를 그대로 따른다
       (칼리 이미지 받기 > 복제 > 첫 실행 > 도구 설치 > 내부망 전환)
    -> 인터넷이 필요한 구간(5단계) 이 있으니 학교 인터넷 정책 확인

  [3-3] 보안 서버에 guardian 올리기
    tar xzf guardian_backup.tgz -C ~
    ls ~/guardian        # config.json, rules, logs, dashboard 확인
    cd ~/guardian
    python3 selftest.py  # 44/44 통과 확인

  [3-4] 이후 4~5단계로 진행

  [3-5] (대안) 칼리 2대를 못 만들 때
    - VM 이 1대뿐이면 "공격자" 를 Windows 10 PC 나 노트북으로 대신할 수
      있다 (nmap, hping3 은 Windows 용도 있음). 단, 공격 테스트
      명령은 attack_test_guide.md 를 그 환경에 맞게 바꿔야 한다.
    - 이 경우 결과가 달라질 수 있으니 팀과 먼저 상의한다.


==================================================================
 4. 옮긴 뒤 설정 다시 맞추기
==================================================================

[4-1] 호스트 전용 네트워크 만들기 (VirtualBox 가 새로 설치된 경우)

  도구(Tools) > 네트워크 > 호스트 전용 > 만들기
   - IPv4 주소 192.168.57.1 / 마스크 255.255.255.0
   - DHCP 서버: 꺼짐
  보안 서버 VM 설정 > 네트워크 > 어댑터 2 > 호스트 전용 선택

  ※ 학교 서버의 다른 사용자가 같은 주소를 쓰고 있다면 다른 대역으로
    바꾼다 (예: 192.168.58.x). 그때는 아래 4-3, 4-4 의 주소도 함께 바꾼다.

[4-2] 인터페이스 이름 / IP 확인 (보안 서버 칼리에서)

  ip a
   - lab 쪽 인터페이스: 192.168.56.10/24 이어야 함 (eth0)
   - mgmt 쪽 인터페이스: 192.168.57.10/24 이어야 함 (eth1)
  인터페이스 이름이 바뀌었으면 (예: enp0s3):
    nmcli con show
    sudo nmcli con mod lab connection.interface-name <새 이름>
    sudo nmcli con up lab
  그리고 ~/guardian/config.json 의 "interface" 도 같이 수정한다.

[4-3] 대시보드 접속 허용 주소

  - ~/guardian/dashboard/dashboard_config.json 의 "host" 가
    192.168.57.10 이어야 한다 (어댑터 2 가 없으면 대시보드가 안 켜짐)
  - 대시보드 토큰은 같은 파일에 그대로 들어 있다 (옮겨져도 유지됨)
  - 새 토큰이 필요하면 "token" 값을 빈 문자열로 바꾸고 다시 실행하면
    새로 만들어진다

[4-4] whitelist

  ~/guardian/config.json 의 "whitelist" 에 새 관리 PC 의 주소를 넣는다.
  (스스로를 차단하지 않게)
   - 호스트 전용망 192.168.57.1
   - 학교 서버 안에서 접속하는 PC 의 주소가 따로 있으면 그것도

[4-5] 원격으로 보는 방법

  - DWAgent 는 더 이상 사용하지 않는다 (옮기지 않음).
  - 학교 가상 컴퓨터에 접속하는 방법(RDP, 학교 원격 도구)을 확인하고
    그 화면에서 VirtualBox 창과 브라우저(대시보드)를 보여주면 된다.
  - 시연을 외부인에게 보여줘야 하면 학교 정책에 맞는 화면 공유
    (Zoom, Teams 등) 를 쓴다.

[4-6] 코드 갱신 방법 (옮긴 뒤에도 같음)

  공유 폴더가 없으면 scp 나 압축 파일로 전달한다. 갱신할 땐 rules/ 와
  logs/ 를 덮어쓰지 않도록 .py 파일과 dashboard/ 만 복사한다.
    cp 새폴더/*.py ~/guardian/
    cp -r 새폴더/dashboard ~/guardian/


==================================================================
 5. 동작 확인
==================================================================

  순서대로 하나씩 확인한다.

  [ ] 두 칼리 VM 이 켜진다 (로그인 가능, 한글 표시)
  [ ] 보안 서버 <-> 공격자 ping 성공
        보안 서버:  ping -c 3 192.168.56.20
        공격자:    ping -c 3 192.168.56.10
  [ ] 인터넷 차단 확인: ping -c 2 8.8.8.8 실패해야 정상
  [ ] cd ~/guardian && python3 selftest.py  -> 44/44 통과
  [ ] sudo python3 guardian.py 실행, 오류 없음
  [ ] python3 dashboard/server.py 실행, "로그인 토큰" 출력 확인
  [ ] 학교 가상 컴퓨터 브라우저에서 http://192.168.57.10:8080 접속
  [ ] 규칙 목록이 그대로 보이고, 켜기/끄기 상태가 유지됨
  [ ] 공격자에서 포트 스캔 -> 대시보드에 탐지 이벤트가 뜸 (dry-run)
  [ ] (선택) 실제 차단 슬라이드 ON -> 차단 -> 해제 흐름 확인
  [ ] 테스트 후 규칙 다시 켜기, dry-run 슬라이드 OFF
  [ ] 스냅샷 "이전완료" 를 새 환경에서 찍는다

[확인] 위 항목이 모두 체크되면 이전 완료. 이전 환경은 최소 일주일
       삭제하지 말고 보관한다.


==================================================================
 6. 문제 해결 모음
==================================================================

  증상: 가져오기에서 "VT-x/AMD-V 를 사용할 수 없음" 으로 VM 이 안 켜짐
  -> 학교 가상 컴퓨터에 중첩 가상화가 꺼져 있다. 관리자에게 켜 달라고
     요청한다. (사용자가 직접 바꿀 수 없는 경우가 대부분)

  증상: 가져오기 중 오류 "VERR_..." 또는 디스크 부족
  -> 빈 공간이 모자란 것. 디스크 여유를 늘리거나 다른 드라이브에
     가져오기 위치를 지정한다.

  증상: 켜졌는데 네트워크가 안 됨 / ip a 에 IP 가 없음
  -> 어댑터 1 이 내부 네트워크 lab 인지 확인
  -> nmcli con show 로 lab 연결이 있는지, sudo nmcli con up lab
  -> 인터페이스 이름이 바뀌었는지 (4-2 참고)

  증상: 대시보드가 안 켜짐 (주소를 쓸 수 없다는 오류)
  -> 어댑터 2(호스트 전용) 가 연결되지 않았거나 192.168.57.10 이 없음
     ip a 로 확인. dashboard_config.json 의 host 확인.

  증상: 대시보드는 켜지는데 브라우저에서 안 열림
  -> 브라우저가 호스트 전용망에 연결된 컴퓨터에서 열렸는지 확인
     (그 컴퓨터에서 ping 192.168.57.10 먼저)

  증상: 로그인 토큰을 모르겠음
  -> 보안 서버에서  cat ~/guardian/dashboard/dashboard_config.json

  증상: 두 VM 이 서로 ping 이 안 됨
  -> 내부 네트워크 이름 lab (대소문자 포함) 동일 / MAC 주소가 서로 다름
     (가져올 때 "MAC 주소 다시 초기화" 를 체크했는지)

  증상: 공유 폴더(/media/sf_...) 가 안 보임
  -> 새 VirtualBox 에서 공유 폴더를 다시 추가하고 "자동 마운트" 체크,
     sudo adduser $USER vboxsf 후 재부팅

  증상: 한글이 깨짐
  -> 한글 글꼴을 다시 설치 (sudo apt install fonts-nanum) 하려면 인터넷이
     필요하다. 어댑터를 잠깐 NAT 로 바꿔서 설치한 뒤 되돌린다.

  증상: 파일 전송 후 import 가 실패 (파일 손상)
  -> 체크섬 비교 (Get-FileHash). 다르면 다시 복사.

  증상: Guardian 이 강제 종료된 뒤 네트워크가 이상함
  -> lab_setup_guide.txt 9단계의 iptables GUARDIAN 체인 정리 명령 참고
